> **⚠️ Release Candidate Warning**: This is a release candidate intended for final validation before the stable v1.0.0 release. Breaking changes are not expected at this stage, but please test thoroughly before deploying to production.

## Fixes

* **[platform] Fix multiple upgrade issues in v0.41→v1.0 migration**: Fixed several issues discovered during upgrade testing of the `migrate-to-version-1.0.sh` script and individual migrations:
  - **Migration 26**: Use `cozystack.io/ui=true` label to locate monitoring HelmReleases (ensuring compatibility with older v0.41.1 clusters where the new label may not yet exist), add robust helm secret deletion with fallback by name pattern and post-deletion verification.
  - **Migrations 28 & 29**: Wrap `grep` in pipelines with `|| true` to prevent `pipefail` exits when no resources match; fix reconcile annotation to use RFC3339 timestamp format; remove protection-webhook handling from migration 29 (it is an external component and should not be managed by cozystack migrations).
  - **Migration 27**: Skip missing CRDs instead of failing the entire migration, add fallback name-pattern secret deletion.
  - **etcd**: Increase HelmRelease timeout from 10m to 30m to accommodate TLS cert rotation hooks.
  - **migrate-to-version-1.0.sh**: Add missing ConfigMap→Package field mappings for `bundle-disable`, `bundle-enable`, `expose-ingress`, and `expose-services`.

  ([**@kvaps**](https://github.com/kvaps) in #2096).

* **[system] Fix monitoring-agents installation failure in tenant clusters**: Resolved an issue where `fluent-bit` failed to start because `_cluster` values are inaccessible from Helm subchart contexts. Replaced all `_cluster.cluster-domain` references with a new `global.clusterDomain` variable that is correctly shared with subcharts. The field is empty by default for the management cluster (uses short DNS names) and is set to the configured cluster domain (e.g. `cozy.local`) for tenant workload clusters, ensuring proper FQDN resolution for cross-cluster metrics and log delivery ([**@kvaps**](https://github.com/kvaps) in #2086).

## Documentation

* **[website] Add breaking changes section to v0.41→v1.0 upgrade guide**: Added a comprehensive "Breaking Changes" section covering MySQL→MariaDB rename, FerretDB removal, virtual-machine split, monitoring restructuring, VPC subnets format, MongoDB config changes, tenant isolation, and internal architecture changes — with before/after examples, resource rename tables, and upgrade warnings ([**@kvaps**](https://github.com/kvaps) in cozystack/website#428).

* **[website] Add tenant Kubernetes cluster log querying guide**: Added documentation for querying logs from tenant Kubernetes clusters in Grafana using VictoriaLogs labels (`tenant`, `kubernetes_namespace_name`, `kubernetes_pod_name`), including the `monitoringAgents` addon as a prerequisite and corrected log query field names ([**@IvanHunters**](https://github.com/IvanHunters) in cozystack/website#430).

* **[website] Add network architecture overview**: Added comprehensive network architecture documentation covering MetalLB (L2/BGP modes), Cilium eBPF as a kube-proxy replacement, Kube-OVN with centralized IPAM, and tenant isolation with identity-based eBPF policies. All diagrams are rendered with Mermaid ([**@IvanHunters**](https://github.com/IvanHunters) in cozystack/website#422).

* **[website] Update certificates section in platform Package**: Updated certificate configuration documentation to reflect the new `publishing.certificates.solver` and `publishing.certificates.issuerName` parameters introduced in v1.0.0-rc.1, replacing the legacy `issuerType` field ([**@myasnikovdaniil**](https://github.com/myasnikovdaniil) in cozystack/website#429).

* **[website] Improve expose-services documentation with idempotent JSON patch commands**: Updated documentation to use `kubectl patch --type=json` for adding elements to arrays instead of replacing whole arrays, preventing accidental data loss when editing service and package configurations ([**@sircthulhu**](https://github.com/sircthulhu) in cozystack/website#427).

* **[website] Add Helm chart development principles**: Added a new "Helm Chart Development Principles" section to the Developer Guide documenting core conventions: easy upstream updates, local-first artifacts, local dev/test workflow, and no external dependencies ([**@kvaps**](https://github.com/kvaps) in cozystack/website#418).

* **[website] Replace non-idempotent CLI commands with idempotent alternatives**: Updated all documentation to use `helm upgrade --install` instead of `helm install`, `kubectl apply -f` instead of `kubectl create -f`, and idempotent namespace creation patterns so that guide commands can be safely re-run without errors ([**@lexfrei**](https://github.com/lexfrei) in cozystack/website#431).
